# Monad Blitz 武汉：赛制与提交约束

> 文档性质：比赛规则参考，不包含任何参赛项目创意、代码或实现资产。<br>
> 资料来源：Monad Blitz 官方 Notion、活动页面及赛前整理记录。<br>
> 最后整理：2026-07-25。

## 1. 活动定位

Monad Blitz 是一场单日、高强度的创意和开发冲刺。参赛者需要在正式比赛时间内，把全新想法快速落地成可演示原型，并在 Monad Testnet 上验证关键机制。

官方强调：

- 探索非常规理念；
- 挑战现有范式；
- 使用 Monad 验证新机制；
- 优先快速原型和真实学习；
- 不追求产品级完美；
- 重视 Monad 开发体验反馈。

核心问题：

> 我们在 Monad 上解决了什么新问题，或者如何用全新的方式解决一个旧问题？

## 3. 硬性规则

### 3.1 团队

- 每队最多 3 人；
- 可以提前组队或现场组队。

### 3.2 原创性

- 参赛项目必须是专门为本次 Monad Blitz 构思的全新项目；
- 正式编码、项目资源和实现工作必须在比赛开始后进行；
- 比赛前可以开展头脑风暴、技术研究和规划；
- 不得直接复制已有应用；
- 不得在没有重大创新或 Monad 独特机制的情况下移植旧项目。

### 3.3 公开性

- 最终参赛仓库必须公开；
- 所有评审所需材料必须能够公开访问；
- 开发期间可以使用 Private 仓库，但提交前必须切换为 Public。

提交前必须验证：

```text
GitHub visibility = PUBLIC
```

### 3.4 前端部署

- 前端必须部署到公网；
- 评委必须能够直接访问；
- 公网部署应在比赛结束后继续保持可用；
- 不能只提交本地页面、CLI 或录屏。

### 3.5 Monad 实机验证

- 项目应在 Monad Testnet 上真实运行；
- 实机演示是 Demo 的核心；
- 智能合约地址、交易哈希和 Explorer 证据应可验证；
- Mock 可以作为稳定演示和后备模式，但不能伪装为真实链上执行。

## 4. 创新要求

官方鼓励：

- 新颖机制；
- 独特想法；
- 探索 Monad 的性能和架构边界；
- 用 Monad 特性创造新的产品体验；
- 快速验证机制是否成立。

官方不鼓励把时间投入到：

- 完美 UI/UX；
- 冗长功能清单；
- 精致但缺少实机内容的演示稿；
- 没有 Monad 必要性的复制项目；
- 大量无法在 Demo 中验证的未来功能。

## 5. Demo 要求

每个团队 Demo 时间为 5 分钟。

建议内容顺序：

1. 用最短时间说明项目做什么；
2. 直接进入实机操作；
3. 展示项目在 Monad Testnet 上的真实运行；
4. 说明使用了哪些 Monad 特性或工具；
5. 解释一个关键技术挑战；
6. 展示合约地址和交易证据；
7. 用一句话总结创新点和商业延展性。

受众主要是开发者，不是投资人。技术机制、真实执行和可验证结果比宏大叙事更重要。

### Demo 备用方案

应提前准备：

- 完整流程录屏；
- 关键步骤截图；
- 已验证的 Testnet 合约；
- 真实交易哈希和 Explorer 链接；
- Mock 演示模式；
- 网络或 RPC 故障时的说明。

备用材料不能替代真实部署，但可以避免现场网络故障导致无法说明成果。

## 6. 评审重点

官方评审综合考虑：

1. 产品是否满足核心要求；
2. 完成度是否足够高；
3. 未来商业模型是否合理。

对项目的实际含义：

- 一条完整闭环优先于十条未完成的功能；
- 合约不能只是装饰；
- 前端必须能够操作或查看真实状态；
- 创新机制必须能在 Demo 中看到；
- 商业模式只需合理，不需要在一天内完整实现。

## 7. MOJO 提交

提交平台：<https://mojo.devnads.com/>

必须提前完成：

- 注册并登录 MOJO；
- 找到当前活动；
- 完成报名；
- 创建或加入团队；
- 确认项目管理面板可以访问。

不要等到 18:30 前才第一次登录或创建项目。

## 8. 提交内容

最终至少准备：

- 公开 GitHub 仓库；
- 公网前端 URL；
- 简洁的项目介绍；
- 安装和运行说明；
- Monad Testnet 合约地址；
- 部署交易哈希；
- 关键交互交易哈希；
- Explorer 链接；
- Demo 视频或备用录屏；
- 安全和已知限制说明。

提交文案应简洁，突出：

- 核心机制；
- Monad 的必要性；
- 已完成的真实闭环；
- 最关键的创新。

不要提交 AI 生成的冗长介绍。

## 9. 提交阻断检查

以下任一项未完成，都可能阻断有效提交：

```text
[ ] GitHub 仓库已经切换为 Public
[ ] 前端公网 URL 可以匿名访问
[ ] Monad Testnet 合约存在真实字节码
[ ] 合约源码已经验证
[ ] 至少一条关键交互交易可以在 Explorer 查看
[ ] README 包含安装、运行、架构和风险说明
[ ] 仓库中没有私钥、助记词、API Key 或 .env
[ ] MOJO 项目已经创建
[ ] Demo 可以在 5 分钟内完成
[ ] 已准备录屏或截图后备方案
[ ] 已收到平台提交确认
```

## 10. 资料边界

本文件只保存赛制和提交规则，不保存：

- 旧项目源码；
- 旧项目创意；
- 旧项目 Sprint 状态；
- 旧项目 Demo 资产；
- 任何在正式比赛开始前创建的参赛实现。

如现场主办方宣布新规则，以现场信息和最新官方页面为准，并立即更新本文件。
